# 分类与提示词约定

更新时间：2026-11-01。本文区分已实现的分类与后续方向。

## 当前分类分为五层

| 层次 | 回答的问题 | 当前内容 | 对生成的影响 |
| --- | --- | --- | --- |
| 主体类别 | 制作什么对象？ | 人物、动物、人形幻想种、兽形幻想种；背景/前景归场景 | 决定资源组合、结构约束和主体专用提示词 |
| 主体属性 | 具体是哪种对象？ | 角色类型、物种／种族、位置；幻想种另有固定身体结构设定 | 骨架与对应参考匹配，多主体按位置一一对应 |
| 资源类型 | 参考图负责什么？ | 骨架、衣服、头像/头部、体表、背景、前景 | 明确每张图的职责与传入顺序 |
| 输出类型 | 最终制作什么图？ | 单张图片、角色资料图、背景资源、前景资源 | 决定构图、分区、透明底及数量要求 |
| 视觉类型 → 蒸馏方案 | 用什么视觉语言表现？ | 12 个视觉类型，通用方案及 117 个具体方案（含 100 个漫画／插画作者研究方案） | 决定媒介、线条、光色、笔触和构图方法 |

“我的上传 / 我的资源”、原图库的站姿、服装季节等 `category` 字段仍是素材标签，不承担主体类别或画风分类。姿势体系、视角、日期、数量、画幅与通道也各自作为筛选属性，互不替代。

## 已实现的资源组合

| 主体 | 资源 | 生成单张图片 | 生成资料图 |
| --- | --- | --- | --- |
| 人物 | 整体骨架 + 每人的衣服、头像 | 自然人体比例、身份、发型、衣装、位置；服装允许反串 | 单角色四视图、头像/表情、服装拆解、材质、姿势还原 |
| 动物 | 整体骨架 + 每只的体表、头部 | 物种结构、姿态、头部特征、毛色/羽色/鳞片与斑纹；保持动物体态 | 单动物四视图、头部/自然表情、体表花纹/材质、姿势还原 |
| 人形幻想种 | 整体骨架 + 每个角色的衣服、头像、体表与附肢 | 人形基础上的局部结构差异，按设定保留翼、蛇尾、多臂等；衣服独立搭配 | 同一结构版本的四视图、头像、衣装拆件、体表与附肢细节、姿势还原 |
| 兽形幻想种 | 整体骨架 + 每个角色的体表与附肢、头部 | 非人形结构及融合部件，保持头、爪、翼、躯干、尾的数量、连接与覆盖边界 | 同一结构版本的四视图、头部、融合部位/体表细节、姿势还原 |
| 场景 | 背景或前景 | 文字或图片制作完整背景 / 透明底前景 | 暂无场景资料图 |

- 动物不是给人物模板换名称。姿态参考根据实际物种的肢体结构生成，适配四足、鸟类、鱼类等，不统一强制四足或人体比例。
- 体表是活体动物全身外观参考，保留各部位颜色、花纹和质感。它不是服装、剥离的皮张、UV 展开或无缝材质贴图。
- 拆解可只选需要的项目。1–6 个主体共用一张整体骨架，其余资源按角色分别制作。动物全选单只 3 张、两只 5 张；只选两只的头部则为 2 张。
- 同一次任务目前选择一种主体类别。同类中可以包含不同物种／种族，例如人形幻想种的天使与娜迦同图，但每个角色的骨架位置、结构、体表和头部必须对应。不同主体类别的混合合成尚未开放。
- 动物物种由用户填写，入库后沿用，不声称自动识别。建议稳定填写“猫”“狗”“赤狐”等同一名称，品种和个体细节写入补充要求。已标注物种的参考会校验一致性；未标注的上传图依靠用户提供的物种与实际图片确认。
- 四类主体都可以组合已有背景和前景，并使用视觉类型及其下属蒸馏方案。资料图每次仅制作一个主体。

## 幻想种的固定结构

人形幻想种和兽形幻想种都必须填写物种／种族及 `anatomy` 身体结构设定（600 字以内）。设定使用自然语言描述头部、肢体与附肢数量、连接位置、融合部位及体表覆盖，不根据种族名称套用唯一答案。例如：

- 天使：人形躯干、两臂两腿、背部一对羽翼；也可以另建三对羽翼的结构版本。
- 娜迦：人形上身、两臂、腰部接一条鳞片蛇尾、无双腿。
- 狮鹫：鹰头与双前爪、狮躯与双后腿、背部一对羽翼、一条狮尾；前半羽毛、后半兽毛。

以上是可编辑的设定示例，不声称这些幻想种只有一种形态。无固定结构的外神不在本次分类中。

结构设定在拆解、入库、生成、角色资料图、历史复用中保留。骨架保存按角色排列的 `roleAnatomies`；头像和体表保存对应角色的 `anatomy`。已标注的骨架、头部、体表必须同时匹配类别、物种／种族与结构版本；结构文本去除首尾空白后逐字比较，不自动判断同义设定。未标注的上传图仍需用户根据图片核对结构。

天然翅膀、尾部、角等属于体表与附肢参考，数量、连接和姿态由骨架及结构设定约束，不作为服装。人形体表资源以中性体块和不透明打底展示，衣物独立拆件。人形幻想种与人物可共用衣服，服装不参与种族、结构或性别绑定；其余身体资源不跨类别混用。

拆解仍支持只选部分资源：人形幻想种全选单个 4 张、两个 7 张；兽形幻想种单个 3 张、两个 5 张。新增主体不强制套用现有普通人体骨架示范。遮挡补全仅在已声明的结构内进行。

## 页面使用

1. 制造资源 → 照片拆解 → 资源主体类别选择“动物”。上传动物图片，填写物种；多只时分别填写位置。
2. 勾选骨架、头部、体表中的所需项，选择通道提交。每张完成即保存，失败可续跑未完成项。
3. 审核后加入资料库，再点击“用这组资源生成图片”。类别、每只物种、资源与位置一起带入。部分入库保留未替换的同类参考；缺少参考或物种不匹配时不能生成。
4. 生成图片左侧按“主体类别”切换，图库仅展示该类资源；背景和前景共用。动物入口显示“动物图片 / 动物资料图”。
5. 已生成图库可组合主体类别、输出类型、视觉类型、蒸馏方案等筛选；历史复用恢复类别和对应角色配置，不自动出图。

## 提示词按类别组织

组合顺序：主体类别与物种结构 → 每张参考职责和角色对应 → 输出构图/资料图分区 → 视觉类型 → 下属蒸馏方案 → 背景/前景层次 → 用户画面要求。

- 人物继续使用现有身份、骨架和穿衣规则。
- 动物有独立拆解提示和 12 种视觉类型提示，避免使用人的皮肤、头发、衣领与服装模板。一般蒸馏方案使用其视觉描述；带明确作者／作品目标的漫画与插画方案使用完整技法提示（含原有四个漫画方案），保留物种结构和体表特征。
- 幻想种有独立拆解和生成提示，参考编号按该类别的实际槽位计算。身体结构设定优先于通用人体／四足约束及风格中的示例造型；资料图所有视角使用同一结构，不为蛇尾补腿、不把融合部件拆成多只动物。
- 场景保持环境透视、空间及透明度规则，不因生成页切到动物而改变资源类别。
- 参考图片里的原始媒介不能覆盖所选视觉类型。提示词只能约束模型；真实画面质量、动物解剖与遮挡补全仍需看图审核。

黑白漫画、彩色漫画各可选择同一组 100 个作者研究方案（80 位漫画家、20 位日系插画师），手绘插画还可选择其中 20 个插画师方案。作者方案不是主体类别；同一方案跨媒介使用时，媒介仍独立参与缓存匹配。出图明确指定作者和代表作品的绘画风格，并传入具体视觉技法；研究卡保留技法来源阶段。风格造型可以重新表现参考主体，但不带入示例角色、故事或固定配色。作者、作品、技法或约束改变时更新内容版本，避免复用旧提示生成的图片。

## 数据与扩展入口

| 位置 | 职责 |
| --- | --- |
| `public/subject-types.js` | 主体类别、名称、资源槽位、主体提示版本、物种输入约束 |
| `public/extraction-settings.js` | 根据类别和所选资源形成任务列表及复用标识 |
| `extraction.mjs` | 人物/动物独立拆解提示 |
| `generation.mjs` | 请求校验、按类别选择成图/资料图提示 |
| `public/job-settings.js` | 参考顺序、类别/物种匹配、完整配置复用、图库筛选 |
| `catalog.mjs` / `server.mjs` | 项目内上传、入库元数据、文件路由和服务端最终校验 |
| `public/effects.js`、`public/manga-effects.js` | 视觉类型及其蒸馏方案；`medium` 为默认父类，`mediums` 声明多个兼容父类 |

主体用 `subjectType: human | animal | fantasy-humanoid | fantasy-beast`；背景/前景推导为 `scene`。体表与附肢使用 `surface`，不占用 `costume`。动物和幻想种角色有 `species`，整体骨架有按角色排列的 `roleSpecies`；幻想种另有 `anatomy`／`roleAnatomies`。数量继续兼容原有 `personCount` 字段。

旧人物资源、任务和草稿没有 `subjectType` 时仍按人物读取，不批量改写旧文件。缓存同时比较主体类别、主体提示版本、物种、幻想种身体结构、完整资源组合、位置、输出类型、视觉类型及版本、蒸馏方案及版本、其他出图参数。不同主体类别及结构设定不互相复用。物种名称去除首尾空白；资源的物种兼容校验忽略英文大小写，同义词不会自动识别。成图复用仍按保存的物种名称逐项比较。

新增类别应补齐：资源槽位与名称、属性校验、拆解/生成/资料图提示、前端配置和筛选、上传入库及历史恢复、复用隔离测试。主体提示改变时升级对应 `revision`；已有结果保留，不自动重新生成。

## 人物的三大件与小件关系

每个角色仍选骨架、衣服、头像。表情已作为原头像的可选属性：一张脸一次选一个表情，默认沿用原表情；多人各自选择。人物编排页可以在头像下填写发型和面部纹身，在衣服下填写头饰及穿搭配饰，在骨架下分配持物与共享道具。小件可选内置描述或上传该类别的参考图片；表情沿用原头像下已生成的图片。

| 选择入口 | 可以挂什么 | 挂到哪里 |
| --- | --- | --- |
| 头像 | 表情、发型、面部纹身 | 绑定具体角色；表情绑定原头像，只替换表情时保留同一张脸 |
| 衣服 | 头饰、项链、耳环、眼镜、背包 | 帽子、发簪、发带、皇冠等可拆卸头饰归入衣服；天然耳、角仍属于头部。换装时可以继续使用同一副眼镜 |
| 骨架 | 手持物、板凳、沙发、滑板、车辆 | 手持物绑定角色的左手或右手；多人共用的物件只在画面中放置一次，再把角色分配到使用位 |

共享物件的使用规则由具体款式声明。容量是可以同时占用的上限，骨架决定画面里有几人。空位允许留空。新增角色仍须选择人数相符的用户骨架。

| 物件 | 使用位 | 合法示例 | 生成前应拦下的情况 |
| --- | --- | --- | --- |
| 滑板 | 1 个滑手位 | A 滑行，B 站在旁边；两人各滑各的要选两块板 | A、B 同时占用同一块板的滑手位 |
| 双座机车 | 驾驶位 1 个、后座 1 个 | A 驾驶，B 可选乘后座；行驶时驾驶者的身体朝向、双手与把手相容 | 两人都占驾驶位、行驶中只有后座乘员、给单座款安排乘客 |
| 双人或三人沙发 | 按款式提供左、右或左、中、右座位 | A 左坐、B 右坐、C 站立，只需一张双人沙发 | 同一位置坐两人；三人都要坐却选双人款 |

制作骨架时需要区分各人的支撑位置、手部接触和动作（如坐在座面、盘腿坐地、骑乘、扶把）。仅有“坐姿”标签不能保证能套上任意座具。图中存在遮挡、没有可靠信息时，保留未知供人确认。生成页先按这些条件筛选，再验证每个占位和互斥的手部动作，提示具体冲突。多人递交同一物件也复用一个实例，分别记录双方接触的位置。

已实现款式、实例及其角色占位随成图保存并参与复用判定。道具按款式定义使用位，可为同款式上传不同参考图。骨架库尚无逐关节接触标注，坐姿、骑姿和实际支撑点由使用者对照原图。例如 A 驾驶/B 后座与 B 驾驶/A 后座是两张不同的图。提示词逐人描述握持、支撑、遮挡和接触阴影，整张画面只渲染一辆机车或一张沙发。
